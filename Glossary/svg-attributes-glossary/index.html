The SVG Attributes Glossary: 45+ Attributes & Properties Explained

Every attribute you'll meet when you open an icon's source — organized by what it does, defined in plain English, and shown in real code. Bookmark this instead of re-Googling preserveAspectRatio.

July 24, 2026 • 15 min read • By IconStash Team

This is the companion to our Icon & SVG terminology glossary. That one defines concepts (sprites, tree-shaking, grids); this one defines the actual attributes and properties in SVG markup and the CSS that styles it. Terms are grouped by function, in the order you encounter them reading an SVG file top to bottom. Open any icon on IconStash and you can match every attribute here against live source.

Document & Coordinate System

xmlns
The XML namespace declaration — xmlns="http://www.w3.org/2000/svg" — that identifies the markup as SVG. Required in standalone .svg files; optional for SVG inlined in HTML5, where the parser already knows.
viewBox
The heart of SVG scaling. Four numbers — min-x min-y width height — defining the internal coordinate canvas. viewBox="0 0 24 24" means all drawing happens in a 24×24 unit space, which the browser scales to the rendered size. Remove it and the icon stops scaling.
Full walkthrough: SVG viewBox explained simply
width / height
The rendered viewport size. With a viewBox present, these control display size only, not the drawing coordinates. Omit them and size the SVG with CSS instead — the preferred pattern for icon components.
Example: <svg viewBox="0 0 24 24" width="16"> renders the 24-unit art at 16px
preserveAspectRatio
Governs what happens when the viewBox ratio and viewport ratio disagree. Default xMidYMid meet scales uniformly and centers (letterboxing if needed). slice crops instead of letterboxes; none stretches and distorts. Icons should virtually always keep the default.
x / y
Position offsets for elements placed inside a coordinate system — <rect>, <use>, <svg>, <text>. Measured in viewBox units, not screen pixels.

Paint: Fill & Color

fill
The interior paint of a shape. Accepts any CSS color, none (hollow — the basis of outline icons), a gradient/pattern reference like url(#grad), or currentColor.
currentColor
Not an attribute but the most important paint value in icon work: it resolves to the element's inherited CSS color. Icons using fill="currentColor" or stroke="currentColor" theme themselves automatically — light mode, dark mode, hover states, everything.
Deep dive: dark mode SVG icons
fill-opacity
Transparency of the fill alone, 0–1, independent of stroke. This is how duotone icons work: the secondary layer is typically the same color at fill-opacity="0.2".
fill-rule
The algorithm deciding which regions of a self-intersecting path are "inside" (and therefore filled): nonzero (default, winding-direction-based) or evenodd (crossing-count-based). When a donut icon renders as a solid circle, a wrong fill-rule is usually the culprit.
opacity
Whole-element transparency, applied after fill and stroke are composited. Unlike fill-opacity/stroke-opacity, it fades the entire icon uniformly — the right tool for disabled states.
color-scheme CSS
A CSS property telling the browser which themes an element supports. Combined with currentColor icons and prefers-color-scheme media queries, it completes an automatic theming pipeline with zero duplicate assets.

Stroke: The Outline Family

stroke
The outline paint. Outline icon libraries (Lucide, Tabler, Feather) are built on fill="none" stroke="currentColor" — all geometry expressed as stroked lines.
stroke-width
Stroke thickness in viewBox units. The signature of a library's visual voice: Feather/Lucide/Tabler use 2 on a 24-grid; Iconoir uses 1.5. Because it's in viewBox units, it scales with the icon — see vector-effect for the exception.
stroke-linecap
The shape of an open path's ends: butt (flat, technical), round (soft, friendly — the icon-library standard), square (flat but extended half a stroke-width past the endpoint).
stroke-linejoin
The shape of corners where segments meet: miter (sharp), round (soft), bevel (clipped). Paired with linecap to define a set's personality — Lucide is round/round.
stroke-miterlimit
Caps how long a sharp miter corner spike may grow at acute angles before being clipped to a bevel. Only relevant with stroke-linejoin="miter"; a common leftover attribute SVGO removes.
stroke-dasharray
Converts a solid stroke into dashes: alternating dash/gap lengths, e.g. stroke-dasharray="4 2". Set it to the path's full length and the entire path becomes a single dash — step one of line-drawing animation.
stroke-dashoffset
Shifts where the dash pattern starts. Step two of line-drawing animation: start offset at the path length (dash pushed fully out of view), then animate to 0 and the icon draws itself.
Tutorial: animate SVG paths with CSS
stroke-opacity
Transparency of the stroke alone, 0–1, independent of fill — the stroke-side twin of fill-opacity.
vector-effect
With non-scaling-stroke, the stroke keeps constant on-screen thickness no matter how much the SVG scales — a 2px stroke stays 2px at 24px or 240px. Powerful for icons that must stay crisp across a wide size range.
pathLength
Overrides the path's computed length for dash calculations. pathLength="100" lets you write dash animations in percentages (stroke-dasharray="100") without measuring real geometry with JavaScript.

Paths & Shape Elements

d
The path data — the drawing itself. A command mini-language: M move, L line, H/V horizontal/vertical line, C/Q cubic/quadratic Bézier, A elliptical arc, Z close. Uppercase = absolute coordinates, lowercase = relative. Every icon is ultimately one or more d strings.
Example: <path d="M3 12h18M12 3v18"/> draws a plus sign
points
The coordinate list of <polyline> (open) and <polygon> (auto-closed) elements: straight segments only, no curves. A checkmark is often just <polyline points="20 6 9 17 4 12"/>.
cx / cy / r
Center coordinates and radius of a <circle>. Ellipses replace r with rx/ry. Dots on notification bells and record buttons are almost always circles, not paths.
rx / ry (on <rect>)
Corner radius of a rectangle. <rect rx="2"> is how icon libraries draw rounded squares without hand-writing arc commands in path data.
x1 / y1 / x2 / y2
Start and end coordinates of a <line> element — and, separately, the direction vector of a <linearGradient>. Simple icon strokes (a minus, an equals sign) are often literal <line> elements.

Transforms

transform
Applies geometric operations to an element or group: translate(x y), rotate(deg cx cy), scale(f), skewX/Y(deg), or a raw matrix(). A chevron-down is frequently a chevron-right with transform="rotate(90 12 12)".
transform-origin CSS
The pivot point for CSS transforms. SVG's default origin is the SVG's 0,0 corner, not the element's center — the classic reason spinner icons orbit wildly instead of spinning in place. Fix: transform-origin: center (with transform-box: fill-box where needed).
scaleX(-1) CSS
The horizontal mirror transform — the standard mechanism for flipping directional icons (arrows, back buttons) in right-to-left locales: [dir="rtl"] .icon-directional { transform: scaleX(-1); }.

Structure & Reuse

<g>
The group element. Attributes set on a group (stroke, fill, transform) cascade to all children — which is how an entire icon inherits stroke="currentColor" from one place instead of repeating it per path.
<defs>
A container for reusable definitions (gradients, clip paths, masks, symbols) that render nothing by themselves. Referenced later by id: fill="url(#brand-gradient)".
<symbol> + <use href>
The sprite mechanism: <symbol id="camera" viewBox="0 0 24 24"> defines an icon once (with its own viewBox); <use href="#camera"/> stamps it anywhere. One HTTP request, one cached file, unlimited reuse.
Example: <svg><use href="/sprite.svg#camera"/></svg>
clip-path
Restricts rendering to a defined region — everything outside the referenced <clipPath> shape is cut off with a hard edge. Binary: a pixel is either shown or not.
mask
Like clip-path but with alpha: the luminance/alpha of the referenced <mask> content controls per-pixel transparency, enabling soft fades and knockout effects (the "cut-out" slash on many crossed-out icons).
id
The reference anchor for defs, gradients, clips, and sprite symbols. The hidden danger: inlining multiple SVGs that share an id (every Figma export names its clip clip0) makes them silently reference each other's definitions. SVGO's prefixIds plugin prevents this.

Gradients

<linearGradient> / <radialGradient>
Paint servers defined in <defs> and applied via fill="url(#id)". Linear gradients run along the x1/y1→x2/y2 vector; radial gradients emanate from a center point.
<stop>, offset, stop-color
The color keyframes inside a gradient: <stop offset="0%" stop-color="#C1DD2D"/>. Two stops make a simple fade; more stops build multi-color ramps.
gradientUnits
The coordinate space of the gradient vector: objectBoundingBox (default — 0–1 relative to the shape) or userSpaceOnUse (absolute viewBox coordinates, letting one gradient flow continuously across multiple shapes).

Accessibility & Interaction

role="img"
Tells assistive technology to treat the SVG as a single image rather than a tree of paths. Standard on meaningful standalone icons, paired with an accessible name from aria-label or <title>.
aria-hidden="true"
Removes the icon from the accessibility tree entirely. Correct for every decorative icon — an icon sitting next to visible text that already says the same thing.
aria-label
The accessible name, placed on the interactive parent of icon-only controls: <button aria-label="Delete"><svg aria-hidden="true">…</svg></button>. The pattern that fixes the #1 icon accessibility failure.
Full patterns: designing accessible SVG icons
<title> / <desc>
SVG-native short label and long description, read by screen readers when the SVG is exposed (and shown as a native tooltip by some browsers). Must be the first children of the <svg>; reference explicitly with aria-labelledby for reliable support.
focusable="false"
A legacy-IE/Edge attribute preventing SVGs from receiving keyboard focus as tab stops. Modern browsers don't focus inline SVGs by default, but component libraries still emit it for safety.
pointer-events
Controls whether the SVG (or a sub-shape) receives mouse/touch events. pointer-events: none on a button's icon guarantees the click always lands on the button — ending the "event.target is a path" class of bugs.

Rendering & Optimization Hints

shape-rendering
A rendering-quality hint: geometricPrecision (favor accuracy), crispEdges (favor sharp axis-aligned edges, disabling some anti-aliasing), optimizeSpeed. Occasionally useful for 1px hairline grid icons; usually best left alone.
paint-order
Reorders fill/stroke/marker painting. paint-order: stroke paints the stroke underneath the fill — the trick behind clean outlined-text badges and icon "halo" outlines without duplicating shapes.
<style> vs presentation attributes
SVG styling has three layers with escalating priority: presentation attributes (fill="red") < CSS (external or <style>) < inline style="". This is why a CSS rule can retheme an icon whose markup hardcodes a fill attribute — but can't beat an inline style. SVGO can convert between forms for smaller output.
data-*
Arbitrary metadata attributes (data-icon="camera") used by icon frameworks for hydration, replacement, and testing hooks. Ignored by renderers, invaluable for tooling.
